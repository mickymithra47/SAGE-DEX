# 14 — EIP-2612: Signature-Based Approvals (Permit Architecture)

## 1. What is EIP-2612?
**EIP-2612** introduces the `permit()` function, extending ERC-20 with gasless approvals via off-chain secp256k1 signatures.

```
USER (Signs structured typed data off-chain with private key)
 │
 ├── Signature (v, r, s, deadline, nonce, spender, value)
 │
RELAYER / ROUTER (Submits transaction on-chain and pays gas)
 │
 ├── Calls token.permit(owner, spender, value, deadline, v, r, s)
 └── Calls token.transferFrom(owner, pool, value) [In same atomic tx!]
```

---

## 2. The Permit Specification & Typehash

```solidity
bytes32 public constant PERMIT_TYPEHASH = 
    keccak256("Permit(address owner,address spender,uint256 value,uint256 nonce,uint256 deadline)");
```

### Execution Steps Inside `permit()`:
1. Validates that `block.timestamp <= deadline`.
2. Encodes the `structHash`:
   $$\text{structHash} = \text{keccak256}(\text{abi.encode}(\text{PERMIT\_TYPEHASH}, \text{owner}, \text{spender}, \text{value}, \text{nonces}[\text{owner}]++, \text{deadline}))$$
3. Computes the EIP-712 32-byte digest:
   $$\text{digest} = \text{keccak256}(\text{"\x19\x01"} \parallel \text{DOMAIN\_SEPARATOR} \parallel \text{structHash})$$
4. Recovers signer address via `ecrecover(digest, v, r, s)`.
5. Reverts if `signer == address(0)` or `signer != owner`.
6. Sets `allowance[owner][spender] = value` and emits `Approval`.
