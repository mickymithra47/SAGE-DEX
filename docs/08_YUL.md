# 08 — Yul & Inline Assembly Guide

## 1. What is Yul?
**Yul** is the official intermediate representation and inline assembly language for the EVM. It provides low-level, register-like access to EVM opcodes while eliminating the high-level overhead and safety checks generated by the Solidity compiler.

---

## 2. Why Does a Protocol Engineer Need Yul?
1. **Gas-Critical Hot Paths**: AMM swap loops, square root calculations, and fixed-point math (`wmul`, `wdiv`) execute millions of times per day. Yul enables hand-tuned opcode sequences.
2. **Accessing Special Opcodes**: Opcodes like `TSTORE`, `TLOAD`, `MCOPY`, `PREVRANDAO`, and `CREATE2` are accessible directly in Yul.
3. **Custom Memory & Call Forwarding**: Writing custom generic proxy fallbacks that forward calldata and return data with zero decoding overhead.

---

## 3. Core Yul Syntax & Memory/Storage Opcodes

```
┌─────────────────┬────────────────────────────────────────────────────────────┐
│ Operation       │ Yul Syntax Example                                         │
├─────────────────┼────────────────────────────────────────────────────────────┤
│ Memory Load     │ let val := mload(0x40)                                     │
│ Memory Store    │ mstore(0x00, val)                                          │
│ Memory Copy     │ mcopy(destOffset, srcOffset, length) [EIP-5656, Cancun]    │
│ Storage Load    │ let data := sload(slot)                                    │
│ Storage Store   │ sstore(slot, data)                                         │
│ Transient Load  │ let temp := tload(slot) [EIP-1153, Cancun]                  │
│ Transient Store │ tstore(slot, temp) [EIP-1153, Cancun]                        │
│ Calldata Load   │ let word := calldataload(offset)                           │
│ Calldata Copy   │ calldatacopy(memOffset, calldataOffset, length)            │
│ Return          │ return(memOffset, length)                                  │
│ Revert          │ revert(memOffset, length)                                  │
└─────────────────┴────────────────────────────────────────────────────────────┘
```

## 4. Solidity vs Yul Comparison: Fixed-Point WAD Math

### Solidity Implementation
```solidity
function wmulSolidity(uint256 x, uint256 y) external pure returns (uint256) {
    return (x * y) / 1e18; // Incurs Solidity overflow checks and division setup
}
```

### Hand-Tuned Yul Implementation
```solidity
function wmulYul(uint256 x, uint256 y) external pure returns (uint256 z) {
    bytes4 sel = MathOverflow.selector;
    assembly {
        let prod := mul(x, y)
        // Multiplicative overflow check: prod / x == y
        if iszero(or(iszero(x), eq(div(prod, x), y))) {
            mstore(0x00, sel)
            revert(0x00, 0x04)
        }
        z := div(prod, 1000000000000000000)
    }
}
```

## 5. Security & Safety Rules in Inline Assembly

> [!CAUTION]
> **Yul Bypasses All Solidity Safety Guarantees!**
> 1. No automatic overflow/underflow checks.
> 2. No type safety or bounds checking.
> 3. No memory safety guarantees (overwriting the free memory pointer corrupts subsequent Solidity operations).

### Golden Rules for Inline Assembly:
1. **Never use assembly where Solidity is fast enough.** Reserve Yul strictly for measured, verified micro-optimizations.
2. **Preserve the Free Memory Pointer (`0x40`)**: If writing beyond `0x80`, either allocate memory by updating `0x40` or restrict temporary data to the 64-byte scratch space (`0x00 - 0x3f`).
3. **Always check return values** on low-level `call`, `delegatecall`, and `staticcall`.
