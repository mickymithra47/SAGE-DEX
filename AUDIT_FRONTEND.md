## 2. Findings & Architectural Issues

### [HIGH] Contract Transactions are Mocked with `setTimeout` in `App.tsx`
- **Location**: `frontend/src/App.tsx#L120-L189`
- **Issue**:
In `App.tsx`, transaction handlers (`handleApprove`, `handleSignPermit2`, `handleSwap`, `handleAddLiquidity`, `handleRemoveLiquidity`) do not initiate real Viem wallet client or contract write operations. Instead, they execute simulated `setTimeout()` timers:
```typescript
const handleSwap = async () => {
  setIsActionPending(true);
  setTxStatus('SIGNING');
  setTxSummary(`Swapping ${amountIn} ${tokenIn.symbol} for minimum ${minimumReceived} ${tokenOut.symbol}`);
  setTxModalOpen(true);

  setTimeout(() => {
    setTxStatus('CONFIRMED');
    setTxHash('0x9a8f4c21b34e567890abcdef1234567890abcdef1234567890abcdef12345678');
    setIsActionPending(false);
    setTxSummary(`Successfully swapped ${amountIn} ${tokenIn.symbol} for ${amountOut} ${tokenOut.symbol}!`);
  }, 1500);
};
```
- **Impact**: While the frontend renders the swap and liquidity interfaces with appropriate math calculations, it cannot execute live transactions against a deployed local node or testnet.
- **Remediation**: Wire `useWriteContract()` or Viem `walletClient.writeContract()` passing `ROUTER_ABI` and parameters generated by `txBuilder.ts`.

### [HIGH] Incomplete Calldata Construction & Dummy Selectors in `txBuilder.ts`
- **Location**: `frontend/src/lib/txBuilder.ts`
- **Issue**:
```typescript
export const FUNCTION_SELECTORS = {
  swapExactTokensForTokens: '0x38ed1739',
  swapTokensForExactTokens: '0x8803dbee',
  swapExactETHForTokens: '0x7ff36ab5',
  swapExactTokensForETH: '0x18cbafe5',
  swapExactTokensForTokensWithPermit: '0x12345678', // DUMMY SELECTOR
  swapExactTokensForTokensWithPermit2: '0x87654321', // DUMMY SELECTOR
  approve: '0x095ea7b3'
};

export function buildSwapExactTokensCalldata(params: SwapExactTokensParams): `0x${string}` {
  const selector = FUNCTION_SELECTORS.swapExactTokensForTokens;
  const encodedIn = params.amountIn.toString(16).padStart(64, '0');
  const encodedMin = params.amountOutMin.toString(16).padStart(64, '0');
  return `${selector}${encodedIn}${encodedMin}` as `0x${string}`;
}
```
- **Analysis**:
  1. `buildSwapExactTokensCalldata` only encodes the first two arguments (`amountIn`, `amountOutMin`), completely omitting the dynamic ABI encoding for `path`, `to`, and `deadline`. If sent to a real node, the EVM call will revert due to malformed calldata.
  2. `swapExactTokensForTokensWithPermit` and `swapExactTokensForTokensWithPermit2` use literal placeholder bytes (`0x12345678`, `0x87654321`).
- **Remediation**: Replace manual string concatenation with Viem's `encodeFunctionData({ abi: ROUTER_ABI, functionName: 'swapExactTokensForTokens', args: [...] })`.
